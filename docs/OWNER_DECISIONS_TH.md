## 2. เกณฑ์ accepted ที่มีในโค้ดแล้ว

### ก) แถวประกาศที่ accepted เข้าราคา

ตรวจโดย `PriceSnapshotService::exclusionReason` แถวต้องไม่ถูกตัดออกด้วยเหตุผลใดเลย:

| เหตุผลที่ตัดออก | ความหมาย |
|---|---|
| `NOT_ACCEPTED` | ยังไม่ได้รับการอนุมัติ ไม่มีอนุมัติอัตโนมัติสำหรับแถวจริง |
| `WRONG_PRICE_TYPE` | ไม่ใช่ราคาเสนอขาย (ราคาเสนอขายแยกจากราคาขายจริง) |
| `OUTSIDE_COHORT` | อยู่นอกกลุ่มเปรียบเทียบของรุ่นนั้น |
| flags | ติดธง เช่น ชุดรวม ขายพ่วง ตามหา |
| `INVALID_PRICE` | ราคาใช้ไม่ได้ |
| `DEPOSIT` | เป็นราคามัดจำ |
| `DEFECTIVE` | สินค้าชำรุด |
| `DUPLICATE` | ซ้ำ |
| `MOCK_SOURCE` | ข้อมูลทดสอบ |
| `NEW_PRICE_REFERENCE_SOURCE` | Priceza (ราคาของใหม่ ใช้อ้างอิงเท่านั้น ไม่เข้ากลุ่มราคามือสอง) |
| `INSUFFICIENT_PROVENANCE` | หลักฐานระดับประกาศไม่พอ |

การอนุมัติแถวจริงต้องมี provenance ระดับประกาศ หรือเป็นข้อความที่เจ้าของพิมพ์ไม่มี URL (`Dashboard::decideObservation`). แถวที่เจ้าของคัดลอกเอง (`owner_transcription`) ต้อง:

- มีหัวข้อ ราคา และรหัสประกาศ
- เป็นโดเมนที่อนุญาต: facebook.com, pantip.com, kaidee.com
- ไม่ใช่ลิงก์โปรไฟล์ส่วนตัว และหัวข้อไม่มีเบอร์โทรไทย
- มีหลักฐานที่ตรึงเป็น JSON มาตรฐานพร้อม SHA-256 (ระดับหลักฐาน C/3)

แถวจากเครื่องจับ (`machine_capture`) ต้องมี snapshot และ hash 64 หลักของตัวเองมาด้วย

### ข) รุ่นสินค้าที่ได้ราคาสาธารณะ

- มีแถวที่ใช้ได้อย่างน้อย **3 แถว** (`OwnerIntakePlanner::MIN_ROWS = 3`)
- ถ้าตัวอย่างแยกเป็นสองกลุ่มราคา ระบบกันออกให้เจ้าของตรวจประกาศเดิมก่อน
- ป้ายความมั่นใจ (`confidence-v2`): **สูง** ≥ 80, **กลาง** ≥ 60, ต่ำกว่านั้นคือต่ำ
- เพดานตามชนิดหลักฐาน: ข้อความที่เจ้าของรวบรวมอย่างเดียวไม่เกิน **59**; หลักฐานที่คนคัดลอกอย่างเดียวไม่เกิน **79**; จะเกินได้เมื่อมี machine capture ปนอยู่
- หน้าต่างความสด **30 วัน**
- สถานะ calibration เป็น CALIBRATING ได้เมื่อมีแถวจริงที่ตรวจแล้วอย่างน้อย **100 แถว** ข้อมูลทดสอบ (fixture) แยกอีกกลุ่มและไม่นับ

## 3. เกณฑ์ที่เสนอสำหรับหัวข้อที่ยังไม่มีเกณฑ์ (รอเจ้าของเห็นด้วย)

| หัวข้อ | นับว่า accepted เมื่อ |
|---|---|
| ไฟล์แรก (L-1) | dry-run ไม่มีรหัสข้อผิดพลาดที่แก้ไม่ได้; เจ้าของตรวจครบทุกแถวในคิว; แถวที่พบว่าราคาผิดหรือผิดรุ่นไม่เกินเพดานที่เจ้าของกำหนด (ตัวอย่าง: ไม่เกิน 1 ใน 10) |
| calibration (L-2) | แถวจริงที่ตรวจแล้วอย่างน้อย 100 แถว และมีการสุ่มตรวจโดยคน ไม่ใช้แถวที่อนุมัติอัตโนมัติ |
| merge PR #4 | เจ้าของอ่าน `PR4_MERGE_BRIEF.md` แล้ว CI ผ่านบน commit สุดท้าย และเจ้าของเลือกวิธี merge |
| อัปเกรด Bootstrap | ชุดเทสต์ผ่าน, ตัวตรวจ vendor ผ่าน, และเจ้าของดูหน้าแอดมินกับหน้าสาธารณะแล้วยอมรับว่าหน้าตาไม่เพี้ยน |
| นโยบายและข้อกำหนด (E-1) | ช่องว่างครบ, ผู้เชี่ยวชาญด้านกฎหมายตรวจแล้ว, เจ้าของอนุมัติ แล้วจึงขออนุมัติงานใส่หน้าเว็บเป็นงานแยก |
| เครื่องมือล้างข้อมูล | เจ้าของกำหนดจำนวนวัน, dry-run บน DEV ได้จำนวนตรงที่คาด, สำรองข้อมูลแล้ว และเจ้าของสั่ง `--apply` เอง |
| ถ้อยคำภาษาไทย | เจ้าของอ่านแล้วบอกว่าใช้ได้ หรือแก้เป็นถ้อยคำของเจ้าของ (แก้ที่จุดเดียว) |
| หมุนเวียนข้อมูลรับรอง | รหัสเดิมใช้ไม่ได้แล้ว, ระบบทำงานด้วยรหัสใหม่, และไม่มีรหัสเดิมเหลือในไฟล์ที่ commit |
| โฮสต์ (C-3, C-4, D-2 ถึง D-5) | แต่ละข้อมีหลักฐานตามเช็กลิสต์ (ผลตรวจ TLS, ผลกู้คืนจากสำรอง, ผลซ้อม deploy) และ `cli/env_preflight.php` ผ่าน |
| beta สาธารณะ (GO) | MUST ครบ 12 ข้อเป็น MET: A-4, A-5, B-1, C-2, C-3, C-4, D-2, D-3, D-4, D-5, E-1, E-3 (เจ้าของทำเอง 6 ข้อ ต้องใช้โฮสต์ 6 ข้อ) ตอนนี้ **NO-GO** |

## 4. สถานะปัจจุบันที่เกี่ยวกับเกณฑ์

- ราคาที่อนุมัติแล้วทุกรุ่นยังมีความมั่นใจ "ต่ำ" และทุกแถวที่อนุมัติเป็นข้อความที่เจ้าของพิมพ์
- มี 22 รุ่นที่รออยู่
- ยังประกอบคอมครบชุดไม่ได้ เพราะยังไม่มีราคาเมนบอร์ด พาวเวอร์ซัพพลาย เคส และชุดระบายความร้อน
- เมตริกจากข้อมูลทดสอบเป็นเพียงฐานทางวิศวกรรม ไม่พิสูจน์คุณภาพกับตลาดจริง
