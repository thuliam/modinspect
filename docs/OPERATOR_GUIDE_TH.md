# คู่มือผู้ดูแล ModInspect (รอบประจำสัปดาห์)

คู่มือนี้เขียนจากเครื่องมือที่มีอยู่จริงในโปรเจกต์ ณ 2026-11-16 ทุกคำสั่งรันจากโฟลเดอร์โปรเจกต์ ถ้าคำสั่งไหนไม่ตรงกับที่เห็น ให้เชื่อโค้ดและ `docs/PROJECT_STATUS.md` ก่อนคู่มือ

## 0. หลักที่ต้องจำ

- ราคาทุกตัวบนเว็บตอนนี้มาจาก **ข้อความที่เจ้าของรวบรวมเอง ไม่มีลิงก์ต้นทาง** จึงถูกจัดเป็นหลักฐานเกรดต่ำ และความน่าเชื่อถือจะไม่เกิน "ต่ำ" ไม่ว่ามีกี่ตัวอย่าง จะขึ้น "กลาง" ได้ก็ต่อเมื่อมีอย่างน้อยหนึ่งแถวจากแหล่งชนิดอื่นที่มีลิงก์ (ดูข้อ 3)
- ราคาที่แสดงเป็น **ราคาประกาศ** ไม่ใช่ราคาปิดดีล และระบบไม่เคยตั้งราคาจากโพสต์ชุมชนโดยตรง ราคามาจากแถวที่ผ่านการอนุมัติ แล้วคำนวณโดยโค้ด PHP เท่านั้น
- ห้ามเปิดไฟล์ LINE ดิบ ห้ามเก็บชื่อผู้ขาย เบอร์โทร ที่อยู่ หรือแชตส่วนตัว ใช้เฉพาะไฟล์ที่ล้างข้อมูลส่วนบุคคลแล้ว (`storage/research/.../research_listings_sanitized.csv`, ไม่ถูก commit)
- ห้ามใช้บริการเสียเงิน ตัวเก็บข้อมูลอัตโนมัติ หรือ API ที่อาจมีค่าใช้จ่าย โดยที่เจ้าของไม่ได้สั่ง (นโยบายงบ 0 บาท)
- ฐานข้อมูล DEV ที่ใช้ร่วมกัน เขียนได้เฉพาะขั้นตอนที่ระบุในคู่มือนี้ เทสต์ใช้ฐานข้อมูลแยก (`.env.testing`) เท่านั้น

## 1. เข้าสู่ระบบแอดมิน

- ใช้ **โฮสต์เดียว** ตามค่า `APP_URL` เสมอ (ตอนนี้ `http://192.168.1.10/modinspect/public/login`) การล็อกอินที่ `modinspect.test` กับ `192.168.1.10` ไม่ใช้ session ร่วมกัน จึงเหมือนต้องล็อกอินใหม่
- ความยาว session ตั้งใน `.env` ได้ (`AUTH_IDLE_TIMEOUT_SECONDS`, `AUTH_ABSOLUTE_LIFETIME_SECONDS`) แต่ **มีผลเฉพาะ `APP_ENV=local` หรือ `testing`** บนเครื่องจริง (production) ค่าคือ 30 นาทีเมื่อไม่ใช้งาน และ 8 ชั่วโมงสูงสุดเสมอ
- สร้างผู้ใช้แอดมินด้วย `php cli/create_admin_user.php` และรีเซ็ตรหัสผ่านด้วย `php cli/reset_admin_password.php` (ไม่เคยพิมพ์หรือเก็บรหัสผ่านในเอกสาร)

## 2. นำเข้าข้อความจากเจ้าของ แล้วอนุมัติ

ทุกขั้นตอนมีโหมดดูก่อน ไม่เขียนข้อมูล ให้ดูผลก่อนรันจริงเสมอ

1. **เตรียมไฟล์นำเข้า** (อ่านไฟล์ที่ล้างแล้ว เขียนไฟล์ JSON ชั่วคราว):
   `php cli/owner_intake_prepare.php --in=storage/research/line_facebook_2026_loc/research_listings_sanitized.csv --category=gpu --out=storage/research/tmp_gpu.json`
   ใช้ `--category=cpu` สำหรับ CPU และ `--spec` สำหรับ RAM/SSD/PSU แถวที่ขาดข้อมูลสำคัญจะถูกข้ามและนับเหตุผลให้ดู (การ์ดจอที่ไม่ระบุ VRAM จะผ่านเฉพาะรุ่นที่ขายขนาดเดียว)
2. **ตัดแถวที่มีอยู่แล้ว**:
   `php cli/owner_intake_filter_existing.php --in=storage/research/tmp_gpu.json --out=storage/research/tmp_gpu_new.json`
   พิมพ์เฉพาะจำนวน (รับเข้า/ซ้ำ/เหลือ) ไม่พิมพ์ข้อความ
3. **ดูผลนำเข้า (ยังไม่เขียน)**:
   `php cli/import_market_evidence.php --file=storage/research/tmp_gpu_new.json --dataset=owner_text --dry-run`
   ดู `valid_rows`, `invalid_rows`, `duplicate_rows` และ `row_errors`
4. **นำเข้าจริง**: คำสั่งเดิมโดยตัด `--dry-run` ออก แถวจะเข้าคิวตรวจเป็น pending ยังไม่ใช่ราคา
5. **ดูแผนอนุมัติ (ยังไม่เขียน)**: `php cli/owner_intake_approve.php --actor=<รหัสผู้ใช้แอดมิน>`
   กฎคือ แถวที่ต่ำกว่า 60% หรือสูงกว่า 160% ของมัธยฐานของสินค้านั้น (รวมแถวที่อนุมัติแล้ว) จะถูกตัดออก สินค้าต้องมีแถวใช้ได้อย่างน้อย 3 แถว และถ้าแถวที่ถูกตัดออกรวมเป็นกลุ่มราคาที่สอง (เช่น RTX 5090 ที่มีทั้ง 3.5–24 พัน และ 170–239 พัน) ระบบจะไม่อนุมัติและบอกว่า BIMODAL ให้คนตัดสินใจ
6. **อนุมัติจริง**: เพิ่ม `--apply` ระบบบันทึกชื่อผู้อนุมัติและคำนวณ snapshot ใหม่ให้
7. **ลบไฟล์ชั่วคราว** ใน `storage/research/` ที่สร้างไว้ในข้อ 1–2

แถว Priceza (REAL) ที่ค้างตรวจอยู่ **ไม่ถูกแตะ** โดยขั้นตอนนี้ ต้องตรวจโดยคนในหน้า Review Queue

## 3. เพิ่มแหล่งข้อมูลที่สอง (ทางเดียวที่ความน่าเชื่อถือจะขึ้นเป็น "กลาง")

ทำตาม `docs/SECOND_SOURCE_INTAKE.md` สั้นๆ คือ กรอกไฟล์ CSV 6 คอลัมน์ที่มีลิงก์ประกาศ (ไม่มีชื่อผู้ขาย) แล้วรัน `--dataset=real` แบบ `--dry-run` ก่อน จากนั้นนำเข้า และอนุมัติทีละแถวด้วยคนในหน้า Review Queue

## 4. ตรวจสุขภาพข้อมูลหลังนำเข้า

- หน้า **Data health** (`/admin/data-health`): สินค้าที่มีราคา ความครอบคลุมต่อหมวด จำนวนที่ค้างตรวจ ความสดของข้อมูล สัดส่วนหลักฐาน และธงลำดับราคา
- หน้า **Snapshot** (`/admin/snapshots/<รหัส>`, ปุ่ม Evidence ในหน้า Price Index): ตัวอย่างที่ใช้ ความน่าเชื่อถือ การ์ด "สิ่งที่ขาดสำหรับ medium" และส่วนต่างจาก snapshot ก่อนหน้า
- `php cli/price_trust_audit.php` ตรวจ replay ของทุกราคาสาธารณะ ต้องเป็น MATCH ทั้งหมด
- `php cli/price_ladder_check.php` เตือนเมื่อรุ่นที่สูงกว่าราคาต่ำกว่ารุ่นต่ำกว่าอย่างชัดเจน (ธงให้คนดู ไม่เปลี่ยนราคา)
- `php cli/resolver_recall_report.php` วัดว่าระบบจับคู่ชื่อสินค้าได้กี่ % และผิดสินค้ากี่ % (เทียบกับตัวสกัดอิสระ)
- `php cli/owner_fill_priority.php` จัดอันดับแถวที่ควรกรอกข้อมูลเพิ่ม (ไม่มีข้อความผู้ขาย)

## 4b. หน้าจอแอดมินที่เพิ่มใน LS-3

- **Owner intake** (`/admin/intake`): เห็นแผนอนุมัติของแถวข้อความจากเจ้าของที่ค้างอยู่ และอัปโหลดไฟล์ CSV ที่ล้างแล้วเพื่อ dry run (ได้ผลเป็นจำนวน ไม่เขียนฐานข้อมูล ไม่เก็บไฟล์) ส่วน *นำเข้าจริง* และ *อนุมัติ* ยังทำที่บรรทัดคำสั่ง (ข้อ 2)
- **Unresolved** (`/admin/unresolved-listings`): รายการที่ระบบจับคู่สินค้าไม่ได้ เลือกสินค้าและ alias เอง ระบบจะปฏิเสธ alias ที่สั้นเกินไป เป็นตัวเลขล้วน ขัดกับชนิดรุ่น (Ti/Super/XT) หรือไปแย่งรายการอื่นที่จับคู่ได้อยู่แล้ว ต้องรัน `php cli/migrate.php` ก่อนจึงจะกดบันทึกได้
- **Users** (`/admin/users`): สร้างผู้ใช้ เปลี่ยนบทบาท ปิด/เปิดบัญชี ตั้งรหัสผ่านใหม่ ปิดบัญชีตัวเองหรือแอดมินคนสุดท้ายไม่ได้ session ที่เปิดอยู่ไม่หลุดเมื่อเปลี่ยนรหัส (ปิดบัญชีก่อนถ้าต้องตัดทันที)
- **Beta readiness** (`/admin/beta-readiness`): อ่านจาก `docs/BETA_READINESS_CHECKLIST.md` และวัดบางข้อสด ๆ ไม่ตัดสินใจแทนคุณ
- ขีดจำกัดการส่งฟอร์มสาธารณะ (Deal Checker 20 ครั้ง และ Build 30 ครั้งต่อ 10 นาทีต่อผู้ใช้): ถ้าเว็บอยู่หลัง reverse proxy ทุกคนจะใช้โควตาเดียวกัน ต้องตั้งค่าที่อยู่ผู้ใช้จริงก่อน

## 5. สำรองและกู้คืน

- สำรอง: `php cli/db_backup.php` ได้ไฟล์ใน `storage/backups/` (บน Linux ตั้งสิทธิ์เจ้าของไฟล์เท่านั้น) ไฟล์นี้มีรหัสผ่านแบบแฮชและข้อความดิบ **ห้าม commit และห้ามส่งต่อ**
- ซ้อมกู้คืนเดือนละครั้ง: `php cli/db_restore.php --file=storage/backups/<ไฟล์>.sql --target-db=<ชื่อ>_restore --verify` ปลายทางต้องลงท้าย `_test` หรือ `_restore` และไม่ใช่ฐานข้อมูลจริง ระบบจะเทียบจำนวนแถวทุกตารางให้ ต้องได้ MATCH
- ยังไม่มีการสำรองอัตโนมัติ การเก็บสำเนานอกเครื่อง และการเข้ารหัสไฟล์ (ต้องตั้งค่าบนโฮสต์จริง คือ HostAtom ตาม DL-014)

## 6. ตรวจระบบก่อนและหลังเปลี่ยนโค้ด

- `/health` ตอบ `{"status":"ok"}` เมื่อฐานข้อมูลพร้อม (503 เมื่อไม่พร้อม)
- `php tests/run.php` (ใช้ `.env.testing` เท่านั้น) ต้องผ่านทุกขั้นตอน และ `php cli/secret_scan.php` ต้องผ่าน
- CI บน GitHub รันชุดเดียวกันบน PHP 8.1, 8.3 และ 8.4 กับ MariaDB 10.6

## 7. เมื่อมีอาการ

| อาการ | ทำอะไร |
|---|---|
| ต้องล็อกอินบ่อย | ดูข้อ 1: ใช้โฮสต์เดียว และตรวจ `APP_ENV` กับค่า `AUTH_*` ใน `.env` |
| หน้าแอดมินขึ้น 403 | ผู้ใช้ไม่มีสิทธิ์: reviewer ดูคิวตรวจและ snapshot ได้ operator คุมแหล่งข้อมูลได้ ส่วน Audit เฉพาะแอดมิน |

| ราคาดูแปลก | ดูธงจาก `price_ladder_check` แล้วเปิดหน้า Snapshot ดูตัวอย่างและส่วนต่างจากครั้งก่อน |
| CI ล้ม | ดูข้อความที่เทสต์พิมพ์ แล้วเทียบกับกฎ Windows/Linux (`tests/linux_parity_scan_test.php`) |

## 8. สิ่งที่ห้ามทำ

อนุมัติแบบกวาดทุกแถวโดยไม่ดูแผน, แก้ราคาหรือสูตรด้วยมือในฐานข้อมูล, นำเข้าไฟล์ที่มีชื่อผู้ขายหรือเบอร์โทร, เปิดตัวเก็บข้อมูลอัตโนมัติ, ใช้ข้อมูลที่แหล่งขอให้หยุดเก็บ (ให้หยุดแหล่งนั้นและบันทึกเหตุการณ์ ห้ามหลบเลี่ยง), commit ไฟล์ `.env` หรือไฟล์สำรองฐานข้อมูล
