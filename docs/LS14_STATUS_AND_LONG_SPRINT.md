# LS-14: สถานะโปรเจกต์เทียบ requirements และแผน Long Sprint

วันที่: 2026-11-18 · ผู้วิเคราะห์: Claude (devteam-plus: Lead + BA + UX/UI + Review)
ฐานอ้างอิง: นิยาม "พร้อม" ของเจ้าของ (DL-098) = เช็กราคา + ข้อมูลสินค้า (ปีวางขาย อายุรุ่น สเปก) + เช็กสภาพ ส่วน marketplace เลื่อนออกไป
หลักฐาน: โค้ดบน `checkpoint/claude-baseline-2026-11-14` (`6da8038`), `docs/PRODUCT_REQUIREMENTS.md`, `docs/BETA_READINESS_CHECKLIST.md`, `docs/SPRINT_BOARD.md`, `docs/REVISE_BACKLOG.md`
และการเปิดเว็บจริงบน DEV (`http://192.168.1.10/modinspect/public`) ที่ 1024 px และ 375 px วันนี้ หลังบ้านดูจากโค้ดและเอกสารเท่านั้น เพราะ pane ไม่ได้ล็อกอิน และผมไม่กรอกรหัสผ่าน

สัญลักษณ์: ✅ ครบ · 🟡 มีแต่ยังไม่ครบ · ❌ ยังไม่มี · 🔒 ติดเจ้าของ (Human Gate)

## สรุปสั้น

- **ฟังก์ชันหลักทั้ง 3 ของ "พร้อม" มีโค้ดครบแล้ว** (เช็กราคา, ข้อมูลสินค้าพร้อมสเปกจากผู้ผลิต, คู่มือเช็กสภาพ) CI ผ่านครบ PHP 8.1/8.3/8.4 และมีเทสต์ 107 ไฟล์
- **ช่องโหว่ใหญ่สุดคือเส้นทางผู้ใช้ (user journey) ไม่ใช่ฟีเจอร์ที่ขาด:** หน้า `/compare` ไม่มีลิงก์จากหน้าไหนเลย (มีแค่ใน sitemap) คู่มือเช็กสภาพเข้าได้จากหน้าสินค้าทางเดียว ทั้งสองอย่างไม่อยู่ในเมนู และ `/seller-price-advisor` ก็ไม่มีทางเข้าเหมือนกัน
- **ข้อมูลยังบาง:** มีราคา 49 จาก 106 รุ่น และความน่าเชื่อถือ "ต่ำ" ทั้งหมด หมวด motherboard, PSU, case และ cooling ยังไม่มีราคาเลย ปัญหานี้แก้ด้วยโค้ดไม่ได้ ต้องเก็บข้อมูลเพิ่ม (F-9)
- **ยังไม่ได้ deploy:** โค้ดยังไม่ขึ้นโฮสต์ (workflow พร้อม แต่รอ merge PR #4 และรอ `.env` บนโฮสต์)
- **Beta checklist:** MUST ที่ยังไม่ผ่านมี 12 แถว ทั้งหมดติดเจ้าของหรือโฮสต์ งานที่ผมทำเองได้ใน sprint นี้จึงเน้น journey, UX และความพร้อมของ ops

## 4. User Journey

**Journey A: ผู้ซื้อเช็กราคา** หน้าแรก → ค้นหา → หน้าสินค้า → Deal Checker ✅ ทางหลักต่อกันครบ
- 🟡 จากหน้าสินค้าไม่มีปุ่ม "เทียบกับรุ่นอื่น" ไปที่ `/compare/{slug}` ทั้งที่ route นี้มีอยู่แล้ว
- 🟡 ผลค้นหาเป็น 0 แสดง did-you-mean และรุ่นยอดนิยม ✅

**Journey B: ผู้ซื้อเช็กดีล** Deal Checker → ผลลัพธ์ → รายการเตือนสภาพ ✅
- 🟡 ผลลัพธ์ยังไม่ลิงก์ไปคู่มือเช็กสภาพของหมวดนั้น และไม่ลิงก์ไปเทียบรุ่น
- 🟡 ผลลัพธ์เปิดได้ด้วย URL เท่านั้น ไม่มีปุ่มแชร์หรือคัดลอกลิงก์

**Journey C: ผู้ซื้อเช็กสภาพก่อนนัดดูของ** ❌ ไม่มีทางเข้าจากเมนู หน้าแรก หรือ footer ทั้งที่เป็น 1 ใน 3 ของนิยาม "พร้อม"

**Journey D: ผู้ซื้อเทียบสองรุ่น** ❌ ไม่มีทางเข้าเลย

**Journey E: ประกอบคอม** 🟡 เข้าได้จากเมนู แต่ 4 หมวดยังล็อก 🔒

**Journey F: Admin ประจำสัปดาห์** (intake → dry run → approve → snapshot) 🟡 ส่วน dry run อยู่บนจอ ส่วน import และ approve ยังเป็น CLI 🔒

**Journey G: เจ้าของ deploy และ rollback** 🟡 workflow พร้อมแต่ยังไม่เคยรัน 🔒

## 5. Recommended (Good to be)

เรียงตามคุ้มค่าต่อแรงที่ใช้ ทุกข้อต้องไม่มีค่าใช้จ่าย

1. ปุ่มคัดลอกลิงก์ผลเช็กดีล + พิมพ์รายการเช็กสภาพ (ใช้ `window.print` และ Bootstrap print utilities)
2. `lastmod` ใน sitemap จาก `calculated_at`
3. Admin: ซ่อนปุ่มที่ role นั้นใช้ไม่ได้ (J-0) และแปลเมนูเป็นไทย
4. หน้า error 404/500 ที่ใช้ธีมเดียวกันและไม่เผยข้อมูลภายใน พร้อมตรวจ log บนโฮสต์
5. Post-deploy smoke script ในเครื่อง (`cli/smoke_check.php`) ใช้ได้ทั้ง workflow และคน
6. ช่องค้นหาชิ้นส่วนใน `/build` บนมือถือ (ใช้ datalist แบบเดียวกับ F-7)
7. Community report v0 ตาม ADR-006 option A 🔒
8. แจ้งเตือนราคา หรือ watchlist (ต้องมีระบบส่งเมล ซึ่งขัดกับนโยบาย 0 บาท) 🔒
9. og:image และรูป WebP 🔒 (สิทธิ์รูปและเครื่องมือ)
10. Search Console + analytics แบบไม่เก็บข้อมูลส่วนตัว 🔒 (บัญชีและข้อความ privacy)
