# Review backend และแผนจัดการงาน (LS-89)

วันที่ 2026-11-28 · อ่านโค้ดและนับจากของจริง ยังไม่ได้แก้ตามแผนนี้
ขอบเขตที่ดู: routing, controller, model/service หลักเรื่องราคาและการตรวจข้อมูล, bootstrap, งาน CLI, migration, เทสต์
**ไม่ได้ดู:** โค้ดทุกบรรทัด, ความปลอดภัยเชิงลึก (ไม่ได้ทำ security review ใหม่), ประสิทธิภาพภายใต้โหลด

## 1. ภาพรวม (ตัวเลขวันนี้)

| รายการ | ค่า |
|---|---|
| ไฟล์ PHP | app 318 · CLI 100 · เทสต์ 192+ |
| ไฟล์ใหญ่สุด | `AdminController.php` 874 บรรทัด (ราว 80 action) · `AdminDataTableService.php` 583 · `Dashboard.php` 405 |
| `global $config` ใน app | 94 จุด |
| กฎ "รุ่นนี้มีราคาสาธารณะ" | เขียนซ้ำราว 18 จุด และใช้เกณฑ์ไม่ตรงกัน (`> 0` กับ `>= 3`) |
| เครื่องมือ | ไม่มี Composer, ไม่มี static analysis |

**ส่วนที่แน่นอยู่แล้ว:** prepared statement, RBAC ฝั่งเซิร์ฟเวอร์พร้อมเทสต์บังคับ guard + CSRF, จำกัดการพยายามล็อกอิน, หน้า error ไม่หลุดข้อมูล, snapshot ทำซ้ำได้, เทสต์ครอบคลุมกว้าง

## 5. ทางเลือก

| ทาง | ชุดงาน | ได้ | เสีย |
|---|---|---|---|
| 1. แน่นแกน | BE-1, BE-2 | ข้อมูลราคาเชื่อได้และพี่ไม่ต้องพึ่ง CLI | โครงสร้างใหญ่และงานปฏิบัติการยังค้าง |
| **2. แน่นแกน + โครงสร้างส่วนที่เจ็บ (แนะนำ)** | BE-1 → BE-2 → BE-4 → BE-3 | ครบวงจร แยกโค้ดราคา/ตรวจให้ดูแลง่าย มีงานประจำวัน | ใช้เวลานาน diff ใหญ่กว่า |
| 3. ครบทุกชุด | BE-1..BE-5 | ฟังก์ชันหลังบ้านครบตามรายการ | ใหญ่มาก ตรวจรับยาก ควรแบ่ง PR หลายรอบ |

**เหตุผลที่แนะนำ 2:** พี่บอกว่าโครงสร้างยังไม่แน่น BE-1 แก้จุดที่ทำข้อมูลผิดได้ก่อน BE-4 ทำหลังจากมีเทสต์ของ BE-1/BE-2 คุ้มกันแล้ว ส่วน BE-5 ยังไม่เร่งเพราะนำเข้าไฟล์ใช้แทนได้

**ลำดับกับงานราคา (T1–T3):** ควรนำของที่แก้แล้วขึ้นเว็บจริงก่อนเริ่ม LS-89
