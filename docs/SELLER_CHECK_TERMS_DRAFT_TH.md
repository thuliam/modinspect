# ร่างเงื่อนไขและขั้นตอนโต้แย้งของ "เช็กผู้ขาย" (ร่าง รอทนาย HG-14 ยังไม่แสดงบนหน้าจริง)

สถานะ: **ร่างให้เจ้าของและทนายตรวจ** ไม่ใช่คำปรึกษากฎหมาย ฟีเจอร์ปิดอยู่ (`SELLER_CHECK_ENABLED=false`) เขียนจากสิ่งที่โค้ดทำจริงตาม `docs/decisions/ADR-007-seller-check-design.md`
ข้อความที่ผู้ใช้เห็นต้องเป็นกลางและบอกข้อเท็จจริง ห้ามใช้คำว่าโกง มิจฉาชีพ ห้ามมีชื่อคน ห้ามมีเปอร์เซ็นต์หรือคำตัดสิน

## 1. ข้อความสำหรับผู้ใช้ (วางใต้ผลค้นหา)

> **ผลนี้คืออะไร**
> นี่คือจำนวนรายงานที่สมาชิกแจ้งเข้ามาและทีมงานตรวจแล้ว ว่ามีเรื่องที่เกี่ยวกับเบอร์โทรหรือบัญชีนี้กี่รายการ แยกตามประเภทปัญหา ไม่ใช่คำพิพากษาของศาล และไม่ใช่การตัดสินว่าผู้ใดทำผิด
>
> **ถ้าไม่พบรายงาน**
> แปลว่ายังไม่มีรายงานที่ตรวจแล้ว ไม่ได้แปลว่าปลอดภัย กรุณาตรวจสินค้าและนัดดูของก่อนจ่ายเสมอ
>
> **ถ้าคุณเป็นผู้ถูกกล่าวถึงและไม่เห็นด้วย**
> คุณโต้แย้งได้ที่หน้า "โต้แย้งรายงาน" โดยกรอกเบอร์หรือบัญชีที่ถูกรายงาน คำอธิบายสั้น ๆ และอีเมลสำหรับติดต่อกลับ ระหว่างที่โต้แย้ง รายงานนั้นจะไม่ถูกนับในผลค้นหา ทีมงานจะตรวจและแจ้งผลกลับตามกำหนดเวลา

## 2. ข้อความสำหรับผู้แจ้ง (ก่อนกดส่ง)

> รายงานของคุณจะถูกตรวจโดยทีมงานก่อนแสดงผลใด ๆ ห้ามใส่ข้อความที่กล่าวหาด้วยคำรุนแรง ชื่อ หรือข้อมูลส่วนตัวของบุคคล ให้เล่าเฉพาะสิ่งที่เกิดขึ้นกับคุณ แนบหลักฐานได้ไม่เกิน 5 ภาพ (หลักฐานเห็นเฉพาะผู้ตรวจ และระบบลบข้อมูลตำแหน่งในภาพให้) ชื่อของคุณจะไม่แสดงต่อสาธารณะ การแจ้งเท็จหรือซ้ำเพื่อกลั่นแกล้งอาจถูกปฏิเสธและจำกัดสิทธิ์

## 3. สิ่งที่ระบบเก็บและไม่เก็บ (จาก ADR-007)

| เก็บ | ไม่เก็บ |
|---|---|
| ค่าแฮชแบบมีกุญแจ (HMAC-SHA-256) ของเบอร์หรือบัญชี | ตัวเลขเบอร์หรือบัญชี |
| เลข 4 ตัวท้าย (หลังบ้านเท่านั้น) | ชื่อ ที่อยู่ โปรไฟล์ รูปของบุคคล |
| ประเภทปัญหาจากรายการ + โน้ตสั้นที่ไม่มีเบอร์ ลิงก์ หรือไลน์ | ข้อความกล่าวหาอิสระ แชต |
| หลักฐานภาพไม่เกิน 5 ภาพ (หลังบ้าน เก็บนอกเว็บ ลบ EXIF/GPS) | การแสดงหลักฐานต่อสาธารณะ |
| รหัสสมาชิกผู้แจ้ง (หลังบ้านเท่านั้น) | ข้อมูลผู้แจ้งบนหน้าสาธารณะ |

## 4. ขั้นตอนโต้แย้ง (ตามโค้ดปัจจุบัน)

1. ผู้ถูกกล่าวถึงเปิดหน้าโต้แย้ง กรอกเบอร์/บัญชี (เป็นการพิสูจน์ว่ารู้หมายเลข) คำอธิบาย และอีเมล (เก็บในรายการโต้แย้งเท่านั้น หลังบ้านเท่านั้น)
2. รายงานที่เกี่ยวข้องเปลี่ยนเป็น `disputed` และ **ไม่ถูกนับ** ทันที
3. ผู้ตรวจ (admin หรือ reviewer) ตัดสิน: คืนเป็น `verified` (ต้องมีเหตุผล) หรือ `rejected` ทุกการตัดสินมีบันทึกผู้ทำ
4. รายงานที่ถูก `rejected` ไม่นับเสมอ

## 5. ข้อที่พี่และทนายต้องตัดสิน (HG-14)

| # | เรื่อง | ค่าที่เสนอ / สถานะ |
|---|---|---|
| 1 | กำหนดเวลาตอบการโต้แย้ง (วัน) | เสนอ 14 วัน ยังไม่มีตัวนับในโค้ด (ผู้ตรวจดูคิวเอง) |
| 2 | แสดงประเภทปัญหาหรือแสดงแค่จำนวน | ตอนนี้แสดงจำนวนและประเภท |
| 3 | ระยะเก็บรายงานที่ค้างหรือไม่ผ่าน | `php cli/retention_purge.php --seller-pending-days=N` พี่เลือก N (ขั้นต่ำ 7) รายงานที่ verified และ disputed ไม่ถูกลบอัตโนมัติ |
| 4 | จำเป็นต้องมีผู้ประสานงานตามกฎหมาย (ช่องทางติดต่อ ขอลบ) ไหม | ทนาย |
| 5 | ถ้อยคำของข้อความสาธารณะข้างบน | ทนาย |
| 6 | ใครเป็นผู้ตรวจ (สิทธิ์ `reports.moderate`) | พี่ |
| 7 | ถ้าผู้ถูกกล่าวถึงขอให้ลบทั้งหมด จะลบแบบใด | ทนาย (ตอนนี้ลบได้ผ่านฐานข้อมูลโดยผู้ดูแล) |

## 6. ที่ผมทำเตรียมไว้แล้ว

- โค้ดทั้งเส้นทางและเทสต์ (`seller_check_test`, `seller_check_http_test`), ซ้อมเปิด/ปิดใน `module_switch_rehearsal_test`
- คำสั่งลบรายงานที่ค้างตามระยะเก็บพร้อมไฟล์หลักฐาน (`--seller-pending-days`)
- preflight ล้มเหลวถ้าเปิดสวิตช์โดยไม่มี key และเตือนให้ยืนยัน HG-14 เมื่อเปิด
