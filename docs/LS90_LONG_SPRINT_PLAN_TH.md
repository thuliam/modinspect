## 2. ปัญหาที่ยังเปิด

1. **ราคา "มือสอง" ปนประกาศของใหม่** เครื่องมืออนุมัติแบบกลุ่มตัดคำเหล่านี้อยู่แล้ว (`app/Services/Research/OwnerApprovalPlan.php:62`) แต่กฎคำนวณราคา (`CohortRules`) ไม่ตัด จับด้วยคำมีผลบวกลวง เช่น "มือ 1.5" หรือ "สภาพเหมือนมือ 1"
2. `/seller-price-advisor` คูณราคาด้วยค่าคงที่ 1.08 / 0.9 / 0.78 ที่ไม่ได้มาจากข้อมูล (`app/Controllers/ModuleController.php:129`)
3. รูปสินค้าไฟล์เดียวใช้ข้ามรุ่น (ตรวจเมื่อ 2026-11-28 ในรอบ LS-88)
4. เว็บจริงไม่มีหน้า `/privacy` และ `/terms`
5. ยังไม่มีการสำรองฐานตามเวลา
6. การ deploy แบบ FTPS อัปโหลดทีละไฟล์ ระหว่างนั้นโค้ดใหม่กับเก่าปนกัน หน้าเว็บมีโอกาส error ชั่วคราว (ประเมินจากลำดับอัปโหลดใน workflow)
7. รายงานความครอบคลุมยังนับแหล่งตามแถว `data_sources` ไม่ใช่ตามแพลตฟอร์ม
8. ความสดของข้อมูล: การจำลองในรอบ LS-88 พบว่าราววันที่ 2026-12-23 จะไม่มีแถว approved ใดอยู่ในช่วง 30 วัน ถ้าไม่เก็บเพิ่ม

## 5. ตัดสินแล้ว 2026-11-28: ทาง C + D

D ในรอบนี้คือกลุ่ม P1 ตาม `docs/marketplace/` เฉพาะส่วนที่ทำได้เองโดยไม่มีค่าใช้จ่าย สร้างแบบ**ปิดสวิตช์ทั้งหมด** ตอนนี้สมาชิก ประกาศขาย และเอกสารกฎหมายในฐานจริงเป็น 0 แถว และยังไม่มีคีย์ OAuth จึงยังไม่มีใครใช้งานได้จนกว่าพี่จะปิดเงื่อนไขในหัวข้อ 6

ค่าที่ใช้: ล็อกอินด้วย OAuth ตามเดิม ไม่เพิ่มอีเมลและรหัสผ่าน · migration เริ่ม 040 เพิ่มตารางหรือคอลัมน์เท่านั้น · หน่วยเงินในตารางใหม่เป็นสตางค์

## 5.1 Prompt สั่งทีเดียว (C + D)

ก่อนส่ง: เครื่องต้องไม่หลับ ถ้าแอปถามอนุญาตระหว่างทาง งานจะหยุดรอ และรอให้รอบขึ้นเว็บ LS-88/89 จบก่อน

### แบบวิ่งจนจบ

```text
/devteam-plus:devteam-plus ทำ LS-90 ทาง C+D ตาม .claude/worktrees/ls89-backend/docs/LS90_LONG_SPRINT_PLAN_TH.md รวดเดียว ไม่ต้องถามระหว่างทาง ใช้ค่าที่แนะนำ
แบ่ง 2 ช่วง ช่วงละ 1 PR: ช่วง 1 = T1-T8, ช่วง 2 = D1-D6 (เริ่มจาก main หลังช่วง 1)
เริ่มบน worktree ใหม่จาก origin/main ล่าสุด และนำไฟล์แผนกับบันทึกรอบขึ้นเว็บที่ยังไม่อยู่ใน main มาด้วย

พี่อนุมัติเฉพาะรอบนี้ ทั้ง 2 ช่วง:
- commit เฉพาะไฟล์ของงานนี้ push สาขา เปิด PR และ merge เข้า main เมื่อ CI เขียวครบเท่านั้น
- deploy ด้วย workflow FTPS (plan ก่อน แล้ว deploy) และรัน smoke check
- ฐานจริง: สำรองก่อน ซ้อมบนสำเนาในเครื่อง แล้วลง migration แบบเพิ่มอย่างเดียวได้ ส่วนคำนวณราคาและกราฟใหม่ทำได้เฉพาะเมื่อ dry-run แสดงว่ารุ่นที่ราคาหายไม่เกิน 6 รุ่น และไม่มีรุ่นที่ยังมีราคาเปลี่ยนราคากลางเกิน 15%
- สร้างงาน Windows Task Scheduler สำหรับสำรองฐานรายวัน 1 งาน
- โฟลเดอร์หลัก studio: เก็บของค้างทั้งหมดเป็นสาขาสำรองและตรวจว่าครบก่อน แล้วจึงอัปเดตให้ตรง main
- ดาวน์โหลด datatables.net-select 1.7.0 และ datatables.net-select-bs4 1.7.0 จาก registry.npmjs.org (MIT ขนาดแตกไฟล์รวมราว 118 KB) ตรวจ hash กับ registry และบันทึก license

ห้าม: อนุมัติ/ปฏิเสธ/แก้ observation, ลบข้อมูลหรือไฟล์ถาวร, DROP/RENAME, เปิดสวิตช์โมดูลใดๆ บนเว็บจริง, แก้ .env บนโฮสต์, เผยแพร่ข้อความกฎหมาย, ดาวน์โหลดอย่างอื่น, ใช้บริการเสียเงิน, ส่งอีเมลหรือ push จริง, เปลี่ยนรหัสผ่าน, ทำงานกลุ่ม P2, เขียน CSS/JS ใหม่เกินโค้ดเชื่อมไม่กี่บรรทัด

ถ้างานใดติด: จดเหตุผลแล้วทำงานถัดไป ถ้า dry-run ราคาเกินเกณฑ์ ไม่เขียนราคาแต่ทำงานอื่นต่อ หยุดทั้งหมดเมื่อสำรองฐานไม่สำเร็จ, เทสต์หรือ CI แดงและแก้ไม่ได้ (ห้าม merge), หรือ smoke check หลัง deploy ล้ม (deploy commit ก่อนหน้าซ้ำ)
จบแต่ละช่วงอัปเดต PROJECT_STATUS และ docs/OWNER_TODO_TH.md รายงานผลจริงพร้อมหลักฐาน
```

## 6. งานที่ต้องเป็นพี่ (ไม่บล็อก LS-90)
