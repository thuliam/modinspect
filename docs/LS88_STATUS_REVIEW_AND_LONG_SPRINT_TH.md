วันที่ 2026-11-28 · ตรวจและอ่านอย่างเดียว ไม่ได้แก้โค้ด ไม่ได้เขียนฐานข้อมูลที่ใช้จริง ไม่ได้ commit/push/deploy

## 1. ข้อสรุป

1. เว็บจริงออนไลน์และผ่าน smoke check 37 ข้อ งานโค้ดขอบเขต "เช็กราคา + ข้อมูลสินค้า + เช็กสภาพ" ทำไปมากแล้ว

3. **แกนของ Blueprint ที่ว่า "ระบบเก็บข้อมูลเอง" ยังไม่เกิด** ข้อมูลที่อนุมัติทั้งหมดมาจาก Facebook ที่พี่เก็บ ไม่มีงานตั้งเวลาใน repo
4. **ยังไม่พร้อมเปิด beta สาธารณะ** ตามเช็กลิสต์ของโปรเจกต์เอง และผมไม่พบบันทึกคำตัดสิน GO ใน `DECISION_LOG.md`
5. ไม่มีเปอร์เซ็นต์ความคืบหน้ารวมที่เชื่อได้ ตัวเลข 64.6% เป็นของ 2026-11-14 ใช้ไม่ได้แล้ว และหลัง 11-15 ระบุว่า NOT_BASELINED

## 5. งานที่เหลือ

### ผมทำแทนได้
แก้ P0-1, P1-1, P1-2, P2-1, P2-2 · MFA แอดมิน · สคริปต์สำรองข้อมูลอัตโนมัติ · รายการตรวจ pending และรายการข้อมูลที่ต้องเก็บ · จัดเอกสารสถานะใหม่ · ร่างหน้า privacy/terms (ไม่เผยแพร่)

### ต้องเป็นพี่
1. หมุนรหัสผ่านฐานข้อมูลและรหัสที่อยู่ในไฟล์ LINE
2. กรอกช่องว่างในร่าง privacy และให้ผู้รู้กฎหมายตรวจ
3. เก็บประกาศหมวด MB, PSU, case, cooling และเติม CPU/GPU ที่ยังขาด
4. ตรวจหน้าตาเว็บและยอมรับ (B-1) · ตรวจข้อความเช็กลิสต์สภาพ
5. ส่งรูปที่มีสิทธิ์ใช้
6. สร้าง OAuth app (ถ้าจะเปิดสมาชิก)
7. cron สำรองข้อมูลและ uptime monitor บนโฮสต์
8. เปิดเว็บด้วย Chrome ดู service worker

## 7. Prompt สำหรับสั่งทีเดียว

ก่อนส่ง: เครื่องต้องไม่หลับ และถ้าแอปถามอนุญาตระหว่างทาง งานจะหยุดรอ

### ทาง B แบบวิ่งจนจบ (รวม merge และ deploy)

```text
/devteam-plus:devteam-plus ทำ LS-88 ทาง B ตาม docs/LS88_STATUS_REVIEW_AND_LONG_SPRINT_TH.md ครบ T1-T8 รวดเดียว ไม่ต้องถามระหว่างทาง ใช้ค่าที่แนะนำในเอกสาร

พี่อนุมัติเฉพาะรอบนี้:
- commit และ push branch studio, เปิด PR, merge เข้า main เมื่อ CI เขียวทั้งหมดเท่านั้น
- deploy ด้วย workflow FTPS (plan ก่อน ถ้าไม่มีการลบไฟล์บน host จึง deploy) แล้วรัน smoke check
- ทำ T1 ก่อน แล้ว deploy เป็น hotfix ทันทีเพื่อเอาราคาผิดออก จากนั้นทำ T2-T8 และ deploy อีกรอบตอนจบ
- ฐานข้อมูลที่ใช้จริง: สำรองก่อน แล้วลง migration แบบ additive และคำนวณ snapshot ใหม่ได้ เมื่อ dry-run แสดง diff แล้วและราคากลางไม่เปลี่ยนจากข้อมูลชุดเดียวกัน
- สร้างงาน Windows Task Scheduler บนเครื่องนี้สำหรับสำรองฐานข้อมูลรายวัน 1 งาน

commit เฉพาะไฟล์ของงานนี้ ห้าม git add -A (มีไฟล์ค้างของงานอื่นใน storage/ และ docs/)
ห้าม: อนุมัติ/ปฏิเสธ observation, ลบข้อมูลหรือไฟล์ถาวร, DROP/RENAME, เปิดสวิตช์โมดูลที่ปิดอยู่, เผยแพร่ข้อความกฎหมาย, ดาวน์โหลดไลบรารีหรือรูป, ใช้บริการเสียเงิน, เปลี่ยนรหัสผ่าน

ถ้างานใดติด: จดเหตุผล ข้ามไปงานถัดไป หยุดทั้งหมดเฉพาะเมื่อสำรองฐานไม่สำเร็จ, เทสต์หรือ CI แดงและแก้ไม่ได้ (ห้าม merge), หรือ smoke check หลัง deploy ล้ม (ถอยกลับ commit ก่อนหน้าแล้ว deploy ซ้ำ)
จบแล้วอัปเดต PROJECT_STATUS และรายงานผลจริงพร้อมหลักฐาน กับรายการที่พี่ต้องทำ
```
