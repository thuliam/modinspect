# LS-31 C: ผลตรวจ alias และการค้นหา (2026-11-21)

ตรวจบนข้อมูล DEV แบบอ่านอย่างเดียว ไม่มีการเพิ่มหรือแก้ alias ในฐานข้อมูล

## สิ่งที่ตรวจ
เครื่องมือใหม่ `php cli/alias_search_probe.php` ค้นด้วยข้อความของ alias ทุกตัว (239 ตัว) แล้วดูว่ารุ่นเจ้าของ alias อยู่ลำดับที่เท่าไรในผลค้นหา

| | ก่อนแก้ | หลังแก้ |
|---|---|---|
| รุ่นเจ้าของอยู่ลำดับแรก | 230 | 239 |
| อยู่ในผลแต่ไม่ใช่ลำดับแรก | 9 | 0 |
| หาไม่เจอ | 0 | 0 |

เก้าตัวที่ไม่ใช่ลำดับแรกคือ "RTX 3060", "RTX 4060", "Ryzen 7 5700X" และ alias ของรุ่นเหล่านี้ เช่น "3060", "5700X" ผลคือค้นรุ่นฐานแล้วเจอรุ่นที่มีชื่อยาวกว่า (3060 Ti, 4060 Ti, 5700X3D) ขึ้นก่อน เพราะรุ่นยาวถูกตั้งเป็นรุ่นยอดนิยมและการจัดเรียงใช้ความนิยมก่อน

## สิ่งที่แก้ (เป็นโค้ด ไม่ใช่ข้อมูล)
`Product::search` เรียงให้รุ่นที่ชื่อเต็ม ชื่อรุ่น หรือ alias ตรงกับคำค้นทุกตัวอักษรขึ้นก่อน จากนั้นจึงเรียงตามความนิยมเหมือนเดิม ถ้าค้นด้วยคำว่างหรือคำที่ไม่ตรงชื่อ ลำดับไม่เปลี่ยน ตัวอย่าง: ค้น "RTX 3060" ได้ 3060 ก่อน 3060 Ti แต่ค้น "3060 ti" ยังได้ Ti ก่อน

เทสต์: `tests/search_exact_first_test.php` ตรวจทุกชื่อและ alias ในแค็ตตาล็อกทดสอบ (190 รายการ) และสร้างรุ่น "... Ti" ยอดนิยมชั่วคราวเพื่อพิสูจน์ว่าไม่แซงรุ่นฐาน (ทดสอบแล้วว่าล้มเมื่อถอนการแก้ออก) ชุด golden เพิ่ม 6 คำค้นแบบ `top` (ข้ามอัตโนมัติถ้าฐานไม่มีรุ่นนั้น)

## รายการที่ไม่แก้และเหตุผล
- **ตัวเลขล้วน 13 ตัว** (เช่น "5090", "3060", "14400"): ผู้ซื้อพิมพ์แบบนี้จริง และตอนนี้รุ่นเจ้าของอยู่ลำดับแรกทุกตัว จึงเสนอให้คงไว้ (พี่ตัดสิน)
- **คู่ที่ขึ้นต้นเหมือนกัน 23 คู่:** เป็นธรรมชาติของชื่อรุ่น (ฐาน กับ Ti/Super/X3D) ไม่ใช่ข้อผิดพลาด ผลหลังแก้ไม่มีคู่ไหนสลับกัน
- **รายการรุ่นที่แค็ตตาล็อกยังไม่มี:** `docs/CATALOG_GAP_PROPOSAL.md` มีตัวเลือก A/B/C รอพี่ตัดสินอยู่แล้ว (แนะนำ A) ผมไม่ได้เพิ่มสินค้า ถ้าพี่เลือกตัวเลือก ผมจะทำ migration ให้
- **ที่ยังไม่ได้ทำ:** ขยายชุด golden ด้วยคำที่คนไทยพิมพ์ผิดจริง ต้องใช้ข้อมูลคำค้นจริงจากผู้ใช้ ซึ่งยังไม่มี (ถ้าเดาเองจะได้ชุดทดสอบที่ไม่สะท้อนความจริง)
