# LS-23: แผนงานยาวถัดไป (เสนอ) — Core feature ก่อน หน้าตาไว้ทีหลัง

วันที่ 2026-11-19 · ต่อจาก LS-22 (`5957835` = `main` = `studio` หลังรวม branch, ลบ `checkpoint` และ `backup`)
กติกาเหมือน LS-17 ถึง LS-22: ไม่ deploy, ไม่เขียนฐาน DEV, ไม่ใช้เงิน, ดาวน์โหลดต้องถามก่อน, ไม่เขียน CSS/JS เองเกินกาว, ราคาจากชุมชน/ผู้ขายไม่กำหนดราคาตลาดโดยตรง, ทุกงานมีเทสต์ และอัปเดต `PROJECT_STATUS.md`
ครั้งนี้เพิ่มสองข้อ: (1) งานหน้าตาไม่อยู่ในแผน ยกเว้นที่พี่สั่งแทรก (2) เรื่องที่พี่แทรกมา ทำทันทีเฉพาะที่เล็ก (ไม่เกินหนึ่งรอบแก้) แล้วจดไว้ใน "รายการที่พี่แทรก" ท้ายไฟล์ งานใหญ่เข้าคิว ไม่ดันงาน core ออก

**สถานะ (2026-11-19):** ทำแล้ว A1 ถึง A3, B1 ถึง B7, C1, C3, E1, E3 (รายละเอียดใน `PROJECT_STATUS.md` และ DL-113) ยังไม่ทำโดยตั้งใจ: B8 (รอข้อความที่พี่อนุมัติ HG-4), D1/D2 (ต้องมี alias จริงจากไฟล์ที่พี่เก็บมา), E2 (จัดกลุ่มช่วยตรวจ), C2 (เหลือเฉพาะรายงานใน C1), C4 (ครอบด้วยเทสต์ของ B3/B7 แล้ว) สิ่งที่ต่างจากแผน: key สเปกใหม่ไม่ต้องมี migration 027 เพราะ `spec_key` เป็นข้อความอิสระ (เพิ่มเฉพาะป้ายชื่อใน `ProductFacts`)

## ทำไมเลือก "ท่อรับข้อมูล" เป็นแกนของ LS-23

ช่องว่างที่ใหญ่ที่สุดของผลิตภัณฑ์ตอนนี้ไม่ใช่โค้ด แต่คือข้อมูล (49 จาก 106 รุ่นมีราคา, 4 หมวดไม่มีราคามือสอง, สเปก RAM/SSD/PSU/เคส/ระบายความร้อนบาง) พี่กำลังไปหาข้อมูลมาให้ตาม master prompt ชุด A ถึง F
ถ้าไฟล์ที่ได้กลับมาต้องนั่งตรวจมือ จะเสียเวลาและพลาดง่าย LS-23 จึงทำให้ "ไฟล์เข้า แล้วรู้ทันทีว่าครบ/ไม่ครบ/ผิดตรงไหน แล้วเข้าระบบอย่างปลอดภัย" ซึ่งเป็น core feature ที่ทุกอย่างหลังจากนี้พึ่งพา
