## ส่วนที่ 2: Modules

### M0: ปิดงานตกหล่น (ครึ่งวัน ทำก่อน)
- เปิด PR `studio` → `main` (6 commit) เพื่อให้ CI รันจริง อ่านผลและแก้ถ้าแดง **การ merge เป็นของพี่**
- อัปเดต `SESSION_HANDOFF.md` ให้ตรง LS-23, แก้ข้อความสถานะ A1 ใน LS-23 ให้ตรงความจริง
- แก้ T-5 (ค่า `speed_min` นอกรายการ) และเพิ่มคอลัมน์ `priority` ใน `B_targets.csv`
- **เสร็จเมื่อ:** CI เขียวบน PR, เอกสารไม่ขัดกับความจริง, เทสต์ครอบ T-5

### M1: เนื้อหาเช็กสภาพ (ข้อมูลชุด E) ครบวง
- ตาราง `condition_checks` (migration แบบเพิ่มอย่างเดียว ลง `schema.sql` และ `modinspect.sql` ตามกฎ), ตัวนำเข้าเป็น "ร่าง", คำสั่งอนุมัติเป็นหมวด (บันทึกผู้อนุมัติ), คู่มือเช็กสภาพและ Deal Checker แสดงเฉพาะที่อนุมัติแล้ว
- ผสานกับข้อตรวจ static เดิมใน `ConditionChecklist` โดยไม่ลบของเดิม
- **เสร็จเมื่อ:** ร่างไม่โผล่หน้าสาธารณะ (เทสต์), อนุมัติแล้วโผล่ที่คู่มือและผล Deal Checker, ครบ 8 หมวดเมื่อมีข้อมูล
- **พึ่ง:** พี่ส่งไฟล์ชุด E และอนุมัติข้อความ (HG-4) ถ้ายังไม่มี ผมทำจนถึงขั้นเทสต์ด้วยข้อมูลสังเคราะห์

### M2: ความน่าเชื่อถือของราคาและความสดของข้อมูล
- สถานะ "ข้อมูลเก่า" คำนวณจากข้อมูลที่เก็บตอนสร้าง snapshot และพิสูจน์ย้อนหลังได้ (กฎเดิม: ไม่เปลี่ยนราคาที่สังเกตได้)
- ท่อรายคืนเดียว `cli/daily_pipeline.php` ปลอดภัยสำหรับ cron: ตรวจโฟลเดอร์ → นำเข้า (dry-run เป็นค่าเริ่มต้น) → รายงานผลต่อ snapshot → บันทึก log เป็นตัวเลขเท่านั้น
- ตัวบ่งชี้ "ช่องว่างราคาเสนอ กับราคาขายจริง" ฝั่งข้อมูล (read model) แสดงเมื่อมีแถวขายจริงที่ตรวจแล้วอย่างน้อย N แถวต่อรุ่น ยังไม่ขึ้นหน้า
- **เสร็จเมื่อ:** เทสต์ย้อนหลังได้ (เวลาผ่านไป สถานะเปลี่ยน ราคาไม่เปลี่ยน), cron dry-run ซ้ำแล้วผลเท่าเดิม

### M3: คุณภาพการจับคู่รุ่นและการค้นหา
- ขยายชุดทดสอบทองด้วย alias จริงจากชุด D, วัด precision/recall ต่อหมวด, กติกา: รุ่นย่อยไม่ถูกรวม (5600 กับ 5600G, 4070 กับ 4070 SUPER)
- ต่อยอด `UnresolvedProposalReport` ให้เสนอ alias ใหม่เป็นไฟล์ให้พี่ตรวจ ไม่เพิ่มเอง
- ปรับค้นหาให้ใช้ alias ใหม่ (ผ่าน SearchQuery เดิม ไม่แตะสูตรราคา)
- **เสร็จเมื่อ:** ไม่มีกรณีเดิมแย่ลง, ตัวเลขต่อหมวดอยู่ใน `docs/`, ข้อเสนอ alias มีหลักฐานแถวอ้างอิงและไม่มีข้อมูลส่วนตัว

### M4: งานตรวจ (Review operations) ลดคอขวดของคน
- รายงานจัดกลุ่มแถวรอตรวจตามรุ่น: ladder, lane, ซ้ำ/โพสต์ซ้ำ, ผลกระทบต่อราคาถ้าอนุมัติ (จำลอง ไม่เขียน)
- โหมด "ตรวจเป็นชุดต่อรุ่น" ในหลังบ้านโดยใช้ DataTables เดิม (ไม่เขียน UI ใหม่) มีกฎ: ห้ามอนุมัติแถว REAL อัตโนมัติ, ต้องมีผู้ตรวจที่ล็อกอิน, บันทึกผู้ทำ
- **เสร็จเมื่อ:** พี่เห็นก่อนว่าอนุมัติรุ่นนี้แล้วราคาและความมั่นใจจะเป็นเท่าไร, เทสต์ครอบสิทธิ์และ audit

### M5: ความพร้อมก่อนขึ้น production (ฝั่งโค้ด)
- สคริปต์ตรวจ host ก่อนขึ้น (ต่อยอด `env_preflight.php`): PHP version/extensions (GD+FreeType, zip), โฟลเดอร์เขียนได้, `.env` ค่าที่ห้ามมีใน production, ตาราง/migration ที่ขาด, ผลเป็นรายการผ่าน/ไม่ผ่านรหัสเดียว
- ซ้อม migration 022 ถึง 026 กับฐาน MariaDB ใน CI (เพิ่มเข้า rehearsal เดิม) และเอกสารขั้นตอนแบบทีละคำสั่งสำหรับ phpMyAdmin
- ตัวอย่าง cron ทั้งหมดในไฟล์เดียว (backup, prune, retention, daily pipeline, ops_probe) พร้อมเตือนว่าต้องรันบน host เอง
- **เสร็จเมื่อ:** รัน `preflight` บนเครื่อง local ได้รายงานครบ, CI ซ้อม migration ผ่านทั้งชุด, พี่มีหน้าเดียวที่ทำตามได้
- **ไม่รวม:** การทำบน host จริง (ต้องเป็นพี่)

### M6: โมดูลที่ปิดอยู่ (สมาชิก, Seller, เช็กผู้ขาย/Blacklist, รายงานชุมชน): เตรียมสวิตช์ (พี่ยืนยัน 2026-11-20: ทำเตรียมไว้ก่อน)
- สำหรับแต่ละโมดูล: runbook "เปิดอย่างไร" (env flag, migration, key, ข้อความที่ต้องอนุมัติ), "ปิดกลับอย่างไร", และเทสต์ซ้อมการเปิดบนฐาน test (เปิด flag แล้วทั้ง flow ผ่าน ปิดแล้วหน้าตอบ 404)
- **Blacklist (เช็กผู้ขาย):** ซ้อมทั้ง flow ในโหมดเปิดบนฐาน test (รายงาน → คิวตรวจหลักฐาน → ค้น → โต้แย้ง → แก้/ถอน), ร่างข้อความโต้แย้งและเงื่อนไข (ร่างเท่านั้น รอทนาย HG-14), รายการตรวจก่อนเปิด (HG-14, HG-18 key, PDPA, ผู้ตรวจ), เทสต์ยืนยันว่าเปิดสวิตช์ไม่ได้ถ้าไม่มี key และปิดแล้ว 404
- ตารางเดียวบอกว่าแต่ละโมดูลรออะไรจากพี่ (HG-13, HG-14, HG-16, HG-17, HG-18, ข้อความ privacy, ผู้ตรวจ, ระยะเก็บ)
- **เสร็จเมื่อ:** เปิดครั้งเดียวทำได้ตามคู่มือโดยไม่ต้องอ่านโค้ด, เทสต์ซ้อมเปิด/ปิดผ่าน
- **ไม่รวม:** การเปิดจริง

### M8: Blog (ฝั่งผู้อ่าน) — เพิ่มตามที่พี่สั่ง 2026-11-20
ตอนนี้มีแค่ตาราง `articles` และหน้าเขียนใน `/admin/articles` ยังไม่มีหน้าอ่าน
- หน้า `/blog` (รายการ แบ่งหน้า ค้นหา) และ `/blog/{slug}` อ่านเฉพาะสถานะ `published` และ `published_at` ไม่เกินปัจจุบัน (ตั้งเวลาเผยแพร่ได้) ร่างและ archived ตอบ 404
- migration แบบเพิ่มอย่างเดียว (ลง `schema.sql` และ `modinspect.sql` ตามกฎ): หมวด, รูปปก (เก็บพาธของไฟล์ที่พี่ให้), ตาราง `article_products` ผูกบทความกับรุ่น
- shortcode ปลอดภัยแบบ whitelist `{{price:slug}}` แสดงการ์ดช่วงราคาสดและกราฟ (ใช้ Chart.js เดิม) ข้อความบทความ escape ทั้งหมด ไม่รับ HTML จากผู้เขียนโดยตรง
- SEO: sitemap, JSON-LD `Article`, og:image, ลิงก์รุ่นที่เกี่ยวข้อง, RSS
- แม่แบบ "ภาพตลาดวันนี้" สร้างร่างบทความจากตัวเลขจริง (ไม่ใช้ AI เขียน) ให้พี่อนุมัติก่อนเผยแพร่
- **เสร็จเมื่อ:** ร่างไม่โผล่สาธารณะ (เทสต์), shortcode ไม่เปิดช่อง XSS (เทสต์ payload), sitemap มีเฉพาะที่ published, ตรวจใน browser ที่ 1440 และ 375 px
- ความคิดเห็นใต้บทความมาจาก Module Community (M9) ไม่ทำซ้ำ

### M9: Community (กระทู้ ความเห็น รีวิว) — โค้ดก่อน ข้อกฎหมายทีหลัง ปิดด้วยสวิตช์

- ตาราง (migration เพิ่มอย่างเดียว): `community_threads` (ผูกรุ่นหรือหัวข้อทั่วไป), `community_posts` (ความเห็น/ตอบ ซ้อนได้ 1 ชั้น), `community_reviews` ("ซื้อแล้วเป็นไง": ราคาที่จ่าย, ประเภทแหล่งซื้อ, สภาพตอนได้รับ, ปัญหาใน 30 วัน, ซื้อซ้ำไหม), `community_votes` (มีประโยชน์), `community_flags` (แจ้งเนื้อหา)
- ต้องล็อกอินเป็นสมาชิก (ระบบสมาชิกมีแล้ว) ชื่อที่แสดงเป็น pseudonym ไม่เก็บชื่อจริง
- ตัวป้องกัน: สแกน PII ทุกข้อความ (เบอร์, LINE ID, อีเมล, ลิงก์) ปฏิเสธอัตโนมัติ, กฎห้ามระบุชื่อ/เบอร์/บัญชีผู้ขายในกระทู้ (ไม่ให้เป็นช่องหมิ่นประมาทแทน blacklist), rate limit ต่อสมาชิก, honeypot, ตัดซ้ำ, ปุ่มแจ้งเนื้อหา, ซ่อนเนื้อหาอัตโนมัติเมื่อถูกแจ้งเกินเกณฑ์ แล้วเข้าคิวให้คนตัดสิน
- หลังบ้าน: คิวตรวจ (DataTables เดิม) ซ่อน/ลบ/ล็อกกระทู้/ระงับสมาชิก บันทึกผู้ทำทุกครั้ง สิทธิ์ `reports.moderate`
- รีวิวแสดงสรุปที่หน้ารุ่นเมื่อมีอย่างน้อย 5 รายการ และบอกจำนวนเสมอ **ไม่กระทบราคา ช่วงราคา ความมั่นใจ หรือ snapshot** (เทสต์ล็อกแบบเดียวกับรายงานชุมชน)
- สวิตช์ `COMMUNITY_FORUM_ENABLED` ค่าเริ่มต้นปิด ทุกเส้นทางตอบ 404 เมื่อปิด ข้อความ privacy/กฎชุมชนเป็นร่างให้พี่อนุมัติทีหลัง (ไม่แสดงจนกว่าเปิด)
- **เสร็จเมื่อ:** flow ครบบนฐาน test (สมัคร/ล็อกอินทดสอบ → โพสต์ → แจ้ง → ซ่อน → ตรวจ), PII ถูกปฏิเสธ, ราคาไม่ขยับ, ปิดสวิตช์แล้วทุกหน้า 404
