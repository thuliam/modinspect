# ขอบเขต pilot ของ ModInspect (ร่างเสนอเจ้าของ)

**สถานะ:** ข้อเสนอของ agent เมื่อ 2026-11-17 ยังไม่ใช่มติ จนกว่าเจ้าของตอบว่า "pilot" และปรับข้อที่ไม่เห็นด้วย เอกสารนี้แยกจาก `docs/BETA_READINESS_CHECKLIST.md` ซึ่งเป็นเกณฑ์ของ **beta สาธารณะ** และไม่ถูกแก้โดยเอกสารนี้

## 1. pilot ต่างจาก beta สาธารณะอย่างไร

| | pilot (เอกสารนี้) | beta สาธารณะ (เช็กลิสต์เดิม) |
|---|---|---|
| ผู้ใช้ | กลุ่มปิด เจ้าของเลือกเอง ไม่ประกาศ ไม่ให้ search engine จัดทำดัชนี | ทุกคน |
| เป้าหมาย | ดูว่าใช้งานได้จริงไหม และเก็บสิ่งที่พบ | เปิดให้คนทั่วไปพึ่งพา |
| ข้อมูลราคา | ใช้เท่าที่มี ความมั่นใจต่ำ บอกตรง ๆ | ต้องมีประกาศระดับรายการที่คนตรวจ และ calibration |
| เกณฑ์ | ข้อ 3 ของเอกสารนี้ | 12 ข้อ MUST ของเช็กลิสต์ (ตอนนี้ NO-GO) |

## 2. สิ่งที่เปิดใน pilot

- เช็กราคา, Deal Checker และ `/build` (ประกอบบางส่วน) ตามที่เป็นอยู่
- ผู้ทดสอบต้องเห็นข้อความนี้ก่อนใช้ (ถ้อยคำสุดท้ายเจ้าของเป็นผู้กำหนด):
  1. ราคามาจากประกาศมือสองที่เจ้าของรวบรวมและตรวจ ความมั่นใจยังต่ำทุกรุ่น
  2. หน้า "ประกอบคอม" ประกอบครบชุดยังไม่ได้ เมนบอร์ด พาวเวอร์ซัพพลาย เคส และชุดระบายความร้อนยังไม่มีราคา
  3. คำแนะนำสเปกเลือกตามราคาและส่วนแบ่งงบ ไม่ได้วัดความแรง
- ไม่แสดงตัวเลขดิบหรือ tier ที่คำนวณจากแหล่งประสิทธิภาพที่ยังไม่ได้รับสิทธิ์ (ดู `docs/PERF_SCORE_RESEARCH.md`)
- ไม่เก็บชื่อ เบอร์โทร ที่อยู่ หรือแชทส่วนตัวของผู้ทดสอบหรือผู้ขาย (กฎโครงการ)

## 3. เกณฑ์ pilot

### ห้ามผ่อน (ต้องผ่านก่อนให้คนอื่นเข้า)

| รหัสเช็กลิสต์ | เรื่อง | เหตุผล | ใครทำ |
|---|---|---|---|
| C-2 | เปลี่ยนรหัสผ่านที่เคยหลุด (รหัสในไฟล์ LINE export และรหัสฐานข้อมูล DEV) | รั่วแล้วเรียกคืนไม่ได้ | เจ้าของ |
| C-3 | โฮสต์ที่เข้าผ่าน HTTPS จริง และเปิด HSTS | ผู้ทดสอบเปิดผ่านอินเทอร์เน็ต | เจ้าของ + โฮสต์ |
| C-4 | `APP_ENV=production` และตรวจ `.env` บนโฮสต์ด้วย `php cli/env_preflight.php` | กันค่าตั้งผิดบนเครื่องจริง | เจ้าของ + โฮสต์ |
| D-2 | สำรองฐานข้อมูลก่อนเปิด และมีสำเนานอกเครื่อง | ข้อมูลรวบรวมด้วยมือหายแล้วทำใหม่ยาก | เจ้าของ + โฮสต์ |
| E-1 (ฉบับสั้น) | ข้อความความเป็นส่วนตัวสั้น ๆ ก่อนรับข้อมูลใคร: ระบบเก็บที่อยู่ IP เพื่อจำกัดคำขอ และบันทึกสเปกเป็นลิงก์ที่แชร์ได้ | มีการเก็บข้อมูลผู้ใช้จริง ร่างเต็มอยู่ที่ `docs/PRIVACY_TERMS_DRAFT_TH.md` เจ้าของต้องกรอกช่องว่าง | เจ้าของ |
| ใหม่ | ตั้งให้ search engine ไม่ทำดัชนี (กลุ่มปิด) | ไม่ให้ pilot กลายเป็นเปิดสาธารณะโดยไม่ตั้งใจ | agent ทำได้เมื่อเจ้าของสั่ง (ไฟล์ robots/ส่วนหัวหน้า) |

### ผ่อนได้ใน pilot (แต่ต้องบันทึกว่ายังไม่ผ่านสำหรับ beta)

| รหัส | เรื่อง | ที่ยอมรับใน pilot |
|---|---|---|
| A-4, A-5 | ประกาศระดับรายการที่คนตรวจ และ calibration | ใช้ข้อมูลที่มี ติดป้ายความมั่นใจต่ำ |
| B-1 | เจ้าของลงนามหน้าตา | ดูเองระหว่าง pilot |
| E-3 | สิทธิ์โลโก้และรูป | ใช้รูปที่มีเครดิตแหล่งใช้ฟรีอยู่แล้ว เจ้าของยืนยันโลโก้ของตัวเอง |
| D-3 | uptime monitor | ผู้ทดสอบแจ้งเองได้ ถ้ามีเวลาติดตั้งภายหลัง |
| D-4 | ซ้อม deploy บน staging | ต้อง deploy ด้วยแพ็กเกจที่ทำ dry run ไว้แล้ว มีสำรองก่อน และเจ้าของสั่ง deploy เอง |
| D-5 | กฎบีบอัดและแคชบนโฮสต์ | ไม่กระทบความถูกต้อง |

## 4. ใครทำอะไร

- **เจ้าของ:** เปลี่ยนรหัสผ่าน (C-2), ตัดสินใจ "pilot", เลือกผู้ทดสอบ, กรอกข้อความความเป็นส่วนตัวฉบับสั้น (E-1), อนุมัติถ้อยคำป้าย "ทดลอง", **เก็บประกาศมือสองของเมนบอร์ด พาวเวอร์ซัพพลาย เคส และชุดระบายความร้อน** และส่งไฟล์ชุดแรก (L-1)
- **โฮสต์ (เจ้าของสั่งหรือทำร่วม):** HTTPS และ HSTS, `.env` production, cron สำรองข้อมูลพร้อมสำเนานอกเครื่อง
- **agent:** ตรวจ `cli/env_preflight.php` เมื่อมีผลจากโฮสต์, ใส่ป้ายและส่วนหัวห้ามทำดัชนีเมื่อเจ้าของสั่ง, รายงานผลการทดสอบ, ไม่ deploy เองโดยไม่ได้รับอนุญาต

## 5. เมื่อไหร่ถือว่า pilot "ปิด"

1. ครบทุกข้อใน "ห้ามผ่อน"
2. มีผู้ทดสอบกลุ่มปิดใช้งานจริง และบันทึกสิ่งที่พบ (ใช้งานได้ ใช้ยาก ราคาเพี้ยนตรงไหน) ใน `docs/PILOT_FINDINGS.md` (ไฟล์นี้ยังไม่มี จะสร้างเมื่อเริ่ม pilot)
3. สรุปว่าเกณฑ์ beta สาธารณะข้อไหนยังไม่ผ่าน ใช้เช็กลิสต์เดิมเป็นหลัก (12 ข้อ MUST)

**pilot ไม่ต้องรอ:** ข้อมูลราคาครบทุกหมวด ผลประเมินความแรง หรือ tier

## 6. สิ่งที่ pilot ไม่ได้พิสูจน์

- ไม่พิสูจน์คุณภาพราคากับตลาดจริงทั้งหมด (ข้อมูลทั้งหมดที่อนุมัติแล้วเป็นข้อความที่เจ้าของพิมพ์ ความมั่นใจต่ำ)
- ไม่พิสูจน์ว่าแนะนำสเปกแล้วใช้งานได้ตามที่ต้องการ เพราะเลือกตามราคา ไม่ใช่ความแรง
- ไม่แทนการตรวจทางกฎหมาย (E-1 ฉบับเต็ม) ก่อนเปิดสาธารณะ
